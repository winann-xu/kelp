# M0 环境勘测报告（2026-09-19）

结论先行：**三处环境各有障碍，均已实测定位**——① VPS 安全组只放行 22（11010 TCP/UDP 均不可达，我最初一次 TCP 探测的"OPEN"是 Mac 侧代理造成的假阳性）；② Mac 上 Stash 处于 TUN 模式，劫持了到公网的路由（utun6）；③ 50.9 无外网 GitHub/镜像可达性（ghfast 000），需经 VPS/本机中转投递安装包。

## 1. 公网节点 47.116.73.216（阿里云华东·上海）

| 项目 | 实测 |
|---|---|
| 系统 | Ubuntu 24.04.4 LTS，x86_64，内网 IP 172.26.31.214 |
| 资源 | 2 vCPU / **1740 MB RAM** / 40 GB 盘（已用 2.2 GB） |
| 时区 | CST（与本地一致） |
| 监听（安装前） | 仅 22(sshd)、53(systemd-resolved 本地)、323(chrony) |
| 主机防火墙 | iptables 三条链均为 ACCEPT，**无本地规则** → 端口过滤由阿里云安全组承担 |
| 已有服务 | aegis / aliyun assist / chrony / cron / tuned / unattended-upgrades，**无 docker** |
| ip_forward | 0 |
| ulimit -n | 65535 |
| 到 GitHub | **直连超时（000）**；ghfast.top → 200；daocloud → 302 |
| 家 → 它 延迟 | 19.40 ms（3 跳：爱快 → 移动出口 → 阿里云） |

安全组实测（2026-09-19 22:1x）：

| 目标 | 从干净出口 50.9 | 从 Mac（未绑接口） |
|---|---|---|
| tcp/22 | 0.02s 连接成功 | 0.00s 成功（经 Stash TUN） |
| tcp/11010 | **5s 超时** | 0.00s "成功"（假阳性，见下） |
| udp/11010、53、443、3478、9999 | **VPS 侧 tcpdump 抓到 0 个包** | 同左 |

结论：**安全组当前只放行 22**。EasyTier 需要的 `11010 TCP+UDP` 必须由用户在阿里云控制台补规则（或提供具备 ECS 权限的 AccessKey 由脚本代劳）。

### 2.1 关键发现：Mac 侧流量被代理接管（假阳性根源）

```
$ route -n get 47.116.73.216
  interface: utun6            # Stash 的 TUN 设备，而非 en0
$ nc -z 47.116.73.216 11010   # → "succeeded"（0.00s，异常）
$ python3 (bind 192.168.50.10): :22 0.02s 成功 / :11010 6.00s 超时  ← 真实结果
```

影响：
1. 在本机对任意远端端口做连通性测试都不可信（会被 Stash 本地接管），**必须绑定 en0 源地址或改用干净出口（如 50.9）验证**。
2. Mac 上的 EasyTier 节点若直连 VPS 会握手超时（实测 `handshake timeout after 1.98s`）——需在 Stash 中放行目标 IP/端口，或不在 Mac 上跑节点。

## 3. B 站点（NAS 侧 192.168.1.0/24）

- 从 A 站点实测：`192.168.1.1` / `192.168.1.99` 均不可达，本机无 `192.168.1.0/24` 路由，`~/nas-nfs` 未挂载。
- 该站点环境（是否有 Docker/root、出口 IP）**待用户确认**，M2 需要它才能完成跨站点验收。

## 4. 由此产生的设计输入

1. 所有 Egress 连通性判断必须避开 Mac 的 Stash；推荐以 50.9 作为 A 站点节点与网关（FR2/FR3），Mac 节点后置。
2. VPS 侧一切依赖公网可达性的改动（EasyTier 11010、未来的面板端口）都受安全组约束 → 集中一次性申请开端口。
3. 安装包投递链路：GitHub →（ghfast 镜像）→ VPS / Mac →（LAN scp）→ 50.9；SHA-256 三处核对一致（`61b659ea…dfd6`）。
